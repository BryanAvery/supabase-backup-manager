# M1-05 - SwiftUI native macOS application shell

**Status:** Initial M1-05 read-only application implementation. This is not a working backup/restore application and does not close the M1 security or recovery gates.

## Delivered

- A real macOS application target defined in `native/DesktopApp/project.yml`, generated by XcodeGen with a configured bundle identifier, sandbox/network-client entitlements, and a reverse-domain OIDC callback registration.
- A native SwiftUI window with explicit unconfigured, signed-out, signed-in and expired-session states; system-browser sign-in using the merged `SBMNativeAuth` package; project refresh and sign-out. There are no backup, restore, connection-test or write controls.
- `native/DesktopFoundation` contains the independently testable `DashboardModel`. The model shows **only live, authorised project responses**. It clears project rows on expired, revoked or failed requests, including an account switch, and never inserts sample projects into the UI.
- `SBMNativeAuth` now exposes a strictly decoded `ProjectSummary` matching the existing OpenAPI `Project` schema, plus `restoreSession()` that rechecks the stored token with `GET /api/v1/me` before considering a user signed in. Expired tokens are discarded rather than refreshed with hardcoded credentials.
- Accessibility labels, keyboard-accessible native buttons, a visible session expiry and accurate readiness labels. “Recoverable” is presented as catalogue assessment, **not** proof of a successfully tested backup.
- A macOS CI workflow builds the actual unsigned `.app` bundle and runs the desktop-state tests. Existing native auth CI checks its cryptographic and Keychain abstractions.

## Local build

On a Mac with Xcode and Homebrew:

```bash
brew install xcodegen
xcrun swift test --package-path native/AuthFoundation
xcrun swift test --package-path native/DesktopFoundation
cd native/DesktopApp
xcodegen generate
xcodebuild -project SupabaseBackupManager.xcodeproj \
  -scheme SupabaseBackupManager \
  -configuration Debug -destination 'platform=macOS' \
  CODE_SIGNING_ALLOWED=NO build
```

A CI build with signing disabled only verifies compilation and the generated bundle's Info.plist. **It is not a signed or notarised distributable Mac app**. On-device Keychain access, callback registration, external-browser return, multiple-user behaviour and restart tests still require a signed application and an Apple Silicon Mac.

## Secure sign-in configuration

The executable is **locked by default**. It has no bundled IdP, fixture account, token, signing key or live Supabase connection. On first launch it expects a private file called `oidc.json` in the operating system's user `Application Support/SupabaseBackupManager` directory, as resolved by `FileManager.urls(for: .applicationSupportDirectory, in: .userDomainMask)`. When sandboxed, this may be the application's own container-specific directory. The file must be a regular non-symlink file, owned/installed for the relevant user with permissions no wider than `0600`, no more than 16 KiB. Its fields are **public identity-provider configuration only**:

```json
{
  "issuer": "https://id.example.invalid/",
  "authorizationEndpoint": "https://id.example.invalid/authorize",
  "tokenEndpoint": "https://id.example.invalid/token",
  "redirectURI": "org.example.supabasebackupmanager:/oauth/callback",
  "apiBaseURL": "https://127.0.0.1:8765/api/v1",
  "clientID": "example-public-native-client",
  "apiScope": "api.read",
  "requiredACR": "urn:example:approved-mfa",
  "signingKeyID": "example-id-token-key",
  "idTokenRSAPublicKeyDERBase64": "<approved-public-RSA-key-in-PKCS1-DER-base64>"
}
```

The values above are intentionally **non-operational examples**, not approved IdP registration details. Do not put bearer tokens, passwords, client secrets or private keys in this file. The code checks that `redirectURI` matches the callback scheme registered in the app bundle. Its `org.example.supabasebackupmanager` identifier is a **placeholder**: change it to a domain/scheme owned by the deployer, and register it with the chosen IdP **before real account use**. The Go TLS server must be listening locally with the corresponding independently approved resource audience and signing key configuration.

## Tests and acceptance boundaries

- `ProjectContractTests` enforces the OpenAPI environment/readiness enum and UUID identifiers and rejects malformed or fabricated backup-success status values.
- `DashboardModelTests` covers no credentials, verified restoration, empty project memberships, 401/revocation, network failure, expired session, failed account switching, and sign-out both with and without server confirmation.
- `NativeSignInClientTests` covers live `/me` identity verification on restore and expired Keychain credentials.
- `m1-desktop.yml` checks Swift package tests, generates the Xcode app target and checks the unsigned app bundle's registered custom URI scheme.

**Deferred:** approved IdP and MFA profile; signed app bundle and Keychain entitlements; real Mac hardware/browser callback tests; security-denial audit; native credentials and key rotation; secure installation/launchd service; any backup/restore features. M1-04, M1-05 acceptance M1-A09, and full T-13 are not declared complete by CI alone.

No production Supabase data, real credentials or live backup/restore operations are used.
