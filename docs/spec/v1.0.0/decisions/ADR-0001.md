# ADR-0001: Modular recovery-first, Mac-hosted architecture

**Status:** Proposed, awaiting engineering validation | **Date:** 2026-11-03

## Decision
Use Apple Silicon Mac mini as primary coordinator, Go daemon + SQLite catalogue, SwiftUI app, React dashboard, versioned OpenAPI, independent adapter contracts, encrypted content-addressed archives and portable recovery CLI. Remote access via private overlay by default.

## Rationale
A single backup daemon avoids duplicated scheduling; modular adapters reflect distinct Supabase recovery semantics; off-host manifests and keys permit recovery after Mac loss.

## Alternatives considered
- Electron-only desktop: easier UI sharing but larger runtime and less native integration.
- Python daemon: viable, but binary distribution/dependency packaging less straightforward.
- Cloud-managed control plane: higher recurring cost and expanded trust boundary.
- Single monolithic backup file: simpler, but makes selective restore and partial replication costly.

## Consequences
More components and build targets; must maintain Go, Swift, TypeScript and CLI compatibility. Key escrow, provider API rate limits and permissions are release-critical.

## Decisions to validate before coding
Supported macOS versions, self-hosted topology matrix, identity provider, key escrow UX, cloud provider quota constraints, Supabase Cloud managed export capabilities, target dataset sizes, dual-approval policy and data residency.
